## Reusable implementation

- `scripts/qa-v2-ios-claimed-bridge.mjs`: reusable `runIosClaimedCase({plan,oracle,...})`. It uses the **same** `ios-login-device.lock` as the existing DPAPI login bridge, with exclusive `wx` create and matching-token removal; no competing owner takeover. It checks current official 831 Manifest SHA / guarded iOS state, exact USB iPhone, installed signed TestFlight build, case applicability, untouched prior verdict, reviewed case contract fingerprint and intended tap recipe. It opens the existing scoped CoreDevice transport, persists the *real* initial screenshot with SHA256 and native pixel dimensions, and only then invokes the original `qa-v2-official-runner.mjs claim --platform ios --kind ios-physical --screen-width-px <measured>`.
- Each HID action is single-tap only. A distinct business oracle must approve **fresh pre-action image SHA and observed target rectangle**. The bridge rechecks live claim/device owner/build before the touch; requires case-specific post-action expected-state evidence and an independent finalized evidence object. Explicitly declared visual transitions cannot PASS with an unchanged screenshot hash. Formal PASS/FAIL passes the existing `validateProofs` and `record` calls; incomplete run closes the session and releases its own claim. Response-loss after a successful claim is recovered through a current-state ownership check. No loop or background task.
- `scripts/qa-v2-ios-persistent-session.py`: iOS-only bounded read-only `--diagnose-services` path; observes independent display, screenshot and HID service availability under the existing RSD session. It does not touch or capture the phone in diagnosis, and emits service availability/error classes only (no UDID, credentials, window content, or native error arguments).
- CLI read-only evidence/diagnostic endpoints: `node scripts/qa-v2-ios-claimed-bridge.mjs --read-only-probe`, `--diagnose-services`, `--diagnose-prerequisites`. All use the same exclusive iPhone lock. A case-specific independent reviewer/oracle is required for `runIosClaimedCase`; arbitrary CLI `--execute` is intentionally not admitted until such a provider is actually integrated.
