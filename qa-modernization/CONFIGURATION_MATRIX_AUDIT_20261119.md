### ソースと証拠の自動失効

scripts/qa-modernization/configuration-coverage-status.mjs は
従来の設定保存テストだけでなく、上表の実業務テストとS4原本証拠も個別に照合する。
保存操作ごとに「saveReadbackProof」と「webBusinessProof」を独立して持つ。
保存できたケースを webBusinessProof=PASS に変換することは禁止。
公開中の設定保存12種類のすべてに、保存後の影響先を実行した
ローカル業務証拠を紐付けた。従来は7種類のみだったが、
セッション保持時間・注文取消承認・位置制限・店舗情報・レポートも追加した。
ただし非公開画像はテスト用合成画像、メール中継はテスト応答、
印刷はジョブ生成まで、プランはテスト専用のDB状態切替である。
実機・外部サービス・本番Cronの成功を意味しない。
実行したソースのSHA256不一致、未実行、ケース数不足、FAIL、独立DB証拠不足が
あれば限定ローカルのPASSを失効させる。国の選択肢が増えたときは既存6か国一覧との差を
検出し、未検証の国を黙ってPASSに含めない。

対象のコードは test/auto-ci/configuration-*.test.mjs および
scripts/qa-modernization/configuration-*.mjs。
元の test/auto-ci 自動検出とS4共通ワークフローを再利用し、
個別ケースだけの専用ランナーは増やさない。
証拠は test-results/qa-modernization/configuration-business/、
configuration-matrix/、s4/ に保存する。

- Free/Proの本物の販売/購読決済、外部カード・QR決済入金は実施していない

従って限定ローカル回帰判定のみPASS、フル業務網羅 --strict は未完了。
正式PASS/FAILを虚偽に集計しない。作業ファイルは未コミット、本番未反映。

## 2026-11-19 実業務判定への修正

**設定画面でON/OFFを保存・再表示できることだけでは業務PASSにしない。**
実際に設定変更したあと対象業務を実行し、計算結果・DB・帳票・操作権限まで
期待値と一致することが必要。権限は設定テーブルの許否だけではなく、
対象の実ユーザーでログインして業務操作することを必須とする。

### 追加したコミッションの業務E2E

Chromiumで管理者がSC分配と注文別コミッションを設定 →
顧客トークンで実Gatewayに注文 → 提供済み → 現金会計確定 →
会計伝票の担当者割当 → 独立SQLの確定伝票、コミッションスナップショット、
従業員別報酬台帳と照合する。設定ON/OFFの各結果を検証する。

| 操作した設定 | 注文別報酬の期待/結果 | SC分配の期待/結果 |
|---|---:|---:|
| 全OFF | 0 / 0 | 0 / 0 |
| SCのみON | 0 / 0 | 5 / 5 |
| 注文別ON (7.5%) | 7.5 / 7.5 | 0 / 0 |
| 両方ON (15.5%) | 15.5 / 15.5 | 5 / 5 |
| 両方を再OFF | 0 / 0 | 0 / 0 |

固定の業務条件は商品100、SC10、SCスタッフ配分率50%、
対象者1名、税0%。元の注文小計と確定金額110も独立DBで確認する。
設定反映の正誤は、toggleの保存値ではなく会計後の報酬台帳で判断する。

### 対象ユーザー実ログイン・権限変更の業務E2E

管理権限でスタッフに設定権限を付与 →
対象スタッフ自身が実ログイン画面からログイン →
設定画面を開きログイン保持時間を19時間に変更・保存 →
画面再読込後の値と独立SQLを照合 →
スタッフがログインしたまま設定権限を取り消す →
次のアクセスは拒否画面へ遷移し、保存RPCも拒否、
DBは変更されないことを確認する。

初回実行では設定ページを許可しても保存側の
adminMod.saveSettingsの固定管理職ガードにより拒否される不具合を発見。
RPCはすでに共通の実効ページ権限を検証済みのため、
src/gasApi.jsの信頼済みsaveSettingsエントリで二重の役職制限を解消。
他の未認証・権限無し経路や、admin.jsを直接呼ぶ箇所のガードは維持。
本人ログイン、許可後の保存、取消後の拒否までの再テストはPASS。
