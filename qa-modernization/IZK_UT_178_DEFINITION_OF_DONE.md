# IZK-UT-178: 完了条件（固定・未達ならOPEN）

## 目的

単発のテスト実装件数や過去のPASSではなく、**定義済み206件の業務要求を、各実行レーンで有効な独立証拠付きPASSにする**。既存のS4/S5/S6共通基盤と要求台帳を最大限再利用する。要求を削除・緩和・別ケースへ無理に流用して数字だけを埋めることは禁止。

## 完了ゲート

| 指標 | 完了値 | 計測方法 |
| --- | ---: | --- |
| 定義済要求 | 206 / 206 | business-web-scenario-requirements.mjs |
| 実行可能な個別ケースへの紐付け | 206 / 206 | izk-ut-178-completion-gate.mjs |
| **最新ソースの独立証拠付きローカルPASS** | **206 / 206** | 実Chrome/Gateway/物理SQL、または要件に適したS4/workerd試験。偽PASS禁止 |
| 未実装・登録漏れ・未検証・ソース失効 | 0 | 同ゲートの nextActions |
| 未解決の製品NG | 0 | 修正後に**同じ期待結果**で再テスト |
| 正式実機・外部サービスQA | 必要ケースを正式判定 | ローカルPASSと**別台帳**。未実施は実機PASSに変換しない |

**クローズ判定：** LOCAL_REQUIREMENT_GATE_PASS はローカル要件検証の達成のみを意味する。さらに必要な正式QAが全て正式PASSとなり、未解決NG・ブロッカーが0となって初めて IZK-UT-178 CLOSED を認める。製品やテストコードの変更で証拠ハッシュが失効したら自動的に再オープンする。

## 作業中に止めない運用

1. node scripts/qa-modernization/izk-ut-178-completion-gate.mjs --write で全要求の最新状態を集計する。OPEN の間は「完了」「クローズ」と報告しない。結果は docs/qa-modernization/IZK_UT_178_COMPLETION_STATUS.json に書き出す。
2. 残件は NOT_IMPLEMENTED、CASE_NOT_REGISTERED、NOT_VERIFIED、STALE_SOURCE、FAIL の実原因に分ける。優先順は**未解決のP0**、その後P1/P2。ただし失敗した1件に全体を停止させず、原因を記録し他の実行可能な要求へ進む。
3. 実装済みなのに台帳未登録のケースは、ソースハッシュ・PNG SHA・操作履歴・独立SQLオラクルを確認して共通ケース台帳に統合する。PARTIAL／シミュレーション専用／未実機を要件全体のPASSにしない。
4. NGは単に再実行せず、**製品の原因を修正し、元の期待条件・元の証拠形式のまま再テスト**する。再発防止テストも残す。
5. ソース変更中に全件を毎回再実行しない。既存の変更影響ランナーで**依存するケースのみ**再実行し、最後にソースを安定させて差分レーンを検証する。無関係な全面QAを繰り返さない。
6. 並列ワーカーの作成・テスト終了だけでは進捗としない。実装の統合、正式レジストリ、検証済み証拠、最新ソース一致、最後のゲート判定まで責任範囲とする。
7. 正式実機QAや外部環境が不可なら「**正式未実施／ブロッカー**」を明記する。別ケースのローカルPASSで置換しない。

## 進捗の単位とレポート

- **第1指標：** 206件中の最新・独立証拠付き PASS 件数。
- **第2指標：** 登録済件数、P0/P1/P2の未実装、失効証拠、現行FAIL、正式QAの確定PASS/FAIL。
- **補助指標：** 修正・テストファイルの本数、単体テストのPASS数（正式QAには加算禁止）。
- **完了の証拠：** 完了ゲートJSON、S4/S5/S6の個別ケース結果とソースSHA、必要な正式QA台帳の一致。

このファイルの条件を緩和して完了件数を増やすことは、依頼者の明示的な仕様変更がない限り禁止。
