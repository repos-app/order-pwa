# ユーザー本人による実機QA｜60ケース実施台帳（2026-11-14）

## 対象・完了条件

既存の `scripts/qa-user-device-qa.mjs` を唯一のケース正本として、16→60件へ拡張（**44件新規**）。元の16件のIDと記録は保持する。P0=37件、P1=22件、P2=1件。iOS=59件、Android=59件。Apple Sandbox専用とGoogle Play専用は別ケースで、他OS専用を未確認分母に含めない。

本人が **実機・OS・アプリビルド** を指定し、実操作して初めて `/#user-device` の個別ケースをOK/NG/対象外/未確認で保存できる。全60件に手順・事前条件・PASS条件・残す証拠を定義。P0 OKは確認内容または証拠の場所を入力し、確認ダイアログを承認することが必須。NG/対象外も具体的理由が必須。履歴はイベント追記で保持し、他ビルドや他端末のOKは継承しない。

**登録60件 ≠ 実機で60件PASS。** 旧正式OS別台帳の結果、Chromium・npm・S4の自動結果、本人未操作の開発者テストをこの実機判定に足さない。現行の「実機テスト」自動ランナーは別分類であり、Realme/iOSの信頼できる物理証拠が未接続なら未連携のまま。

## 操作と証拠の記録方法

1. Windows PCのQAダッシュボード `http://127.0.0.1:18765/#user-device` を開き、OS・ビルド・端末名を正確に指定。「この実機の結果を表示」を押す。
2. P0／未確認で絞り込む。12件ずつのページを進め、各カードの「操作手順・期待結果・証拠を表示」を展開して操作する。
3. ダミー店舗・Sandboxが前提の削除/購入/復元ケースを**本番店舗・実課金で試さない**。機材やSandboxがなければ理由を記録して対象外とする。
4. 成功した場合は判定OK、P0では証拠の場所と実際の観察結果をメモに入力し、本人確認を承認する。失敗した場合はNG・再現手順・必要なら `IZK-UT-xxx` を記録する。
5. OS・端末またはビルドを変えたら新しい対象として判定する。これまでのOKやChrome/業務テストのPASSを流用しない。

## 現在の不足と次の自動化候補

- 45画面のうち実Chromiumの代表シナリオは22画面に定義済み。23画面はWEBの画面単位シナリオが未定義。売上・会員/クーポンのWEB実操作、店舗日報と会計/経費の突合を優先する。
- 本人の実機ケースを60件定義しても、端末を実際に操作していなければ実機判定は増加しない。ネイティブ自動ランナーの端末接続・証拠署名は別の課題として残る。
- BLEの紙印字、StoreKit/Google Play Sandbox、カメラ・GPSのOS権限、App Store署名ビルド更新はChromeで代替できない。本人実機または将来の署名付き実機自動化で判定する。
