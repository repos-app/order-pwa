# S3 テストケース一覧・ダッシュボード実装報告（2026-11-07）

## 訂正（2026-11-07）：依頼対象は「RPMテスト」ではなく「npm test」

ユーザーから訂正を受け、**最上位分類を「npm test（プログラム自動テスト）」と「業務QA（正式OS別シナリオ）」の2系統**に変更した。下に掲載した初回のRPM／負荷系5分類集計は旧版の記録で、現行画面の最上位分類ではない。

| 現行の系統 | 登録件数 | 正しい解釈 |
|---|---:|---|
| npm test | **217実行ステップ** | package.json の npm test が起動する既存テストパイプラインの登録コマンド（全件実行済みではない） |
| npm test内の自動発見 | 8ファイル | 上記217ステップ中の既存1ステップの**内訳**。別のnpm実行ステップとして加算しない |
| 業務QA | **831固有ケース／1,659 OS別行** | Android829行＋iOS830行。正式QAのPASS/FAIL/BLOCKEDは公式台帳のみを使用 |
| 一覧の表示行総数 | **1,884行** | OS別1,659＋npmステップ217＋その内訳8。表示行数であり、1,884種類の独立した実行ケースではない |

現在のダッシュボードで選べる「テスト系統」は npm test／業務QA。「対象の種類」は両系統に共通の業務機能、負荷・性能、画面・UX、ネイティブ、技術・共通基盤で、**別軸の下位分類**である。特に、npm testの中にも会計・注文等の業務検証があるため、業務機能とnpm testを排他分類にしない。

テスト一覧、API、CSV、実ブラウザでの系統・対象の種類の絞り込みについて、テスト3/3 PASS・0 FAILを確認した。登録のみのnpmコマンドをPASSには変換せず、S2独立証拠付きローカルPASSと正式QA PASSを分けている。

現行の分類・件数の一次原本は docs/qa-modernization/S3_test_case_catalog_summary.json、詳細は docs/qa-modernization/S3_test_case_catalog.csv。実行時点の最新値はダッシュボードの /api/test-catalog が返す（並行開発で件数変動あり）。
